# 시스템 구조 개요

## 서비스 구성

ICL HomePage는 하나의 저장소에서 다음 영역을 운영합니다.

- 브랜드 홈페이지와 커뮤니티
- 회원 인증과 마이페이지
- 교육영상 상품, 구매, 재생과 진도
- 필라테스 스튜디오 일정, 예약, 수강권과 회원 관리
- 관리자 회원, 주문, 환불, 매출과 콘텐츠 관리
- 웹과 Capacitor 기반 Android/iOS 앱

## Frontend

- React 18과 Vite 기반 단일 페이지 애플리케이션입니다.
- `frontend/src/features`는 도메인별 화면과 API 래퍼를 보관합니다.
- `frontend/src/shared`는 공통 API 클라이언트, 세션 상태, 헤더와 플랫폼 분기를 보관합니다.
- 웹과 앱은 같은 React 기능 코드를 사용하며 네이티브에서만 필요한 기능은 런타임으로 분기합니다.

## Backend

- Node.js와 Express 기반 API 서버입니다.
- `backend/src/features`에 인증, 회원, 교육영상, 결제, 환불, 커뮤니티, 스튜디오 기능이 분리되어 있습니다.
- `backend/src/shared`에 DB 연결, 세션 인증, 보안 미들웨어, 이메일과 공통 유틸리티가 있습니다.
- 외부 발송과 결제 호출은 환경별 허용 플래그와 테스트 안전 모드를 거쳐야 합니다.

## 인증

- 로그인은 JWT를 브라우저에 저장하는 방식이 아닙니다.
- 서버가 만든 불투명 세션 토큰을 MySQL `sessions` 테이블에 보관합니다.
- 브라우저는 `icl_session` HttpOnly 쿠키로 세션을 전달합니다.
- 관리자와 스튜디오 직원 권한은 백엔드에서 로그인 계정과 역할을 다시 확인합니다.

## Database

- MySQL을 사용합니다.
- 회원, 세션, 주문, 결제, 환불, 교육영상, 커뮤니티, 스튜디오 운영 테이블을 함께 관리합니다.
- 운영 서버 시작 시 파괴적 스키마 변경은 기본 차단합니다.
- 스키마 변경은 백업과 승인을 거친 별도 migration 절차로 처리합니다.

## 파일과 영상

- 일반 이미지와 첨부 파일은 업로드 루트 아래에 저장합니다.
- 교육영상 원본 경로는 nginx에서 직접 노출하지 않고 인증된 재생 경로를 사용합니다.
- 테스트 환경은 운영 업로드 경로와 분리된 `uploads-test`를 사용합니다.

## 배포

- `main` 브랜치 push가 GitHub Actions EC2 배포를 실행할 수 있습니다.
- 프론트엔드는 Vite build 산출물을 nginx가 제공합니다.
- 백엔드는 PM2로 실행하고 nginx가 `/api`를 프록시합니다.
- `/uploads`의 실제 파일 경로와 nginx alias는 운영 환경에서 반드시 일치해야 합니다.
