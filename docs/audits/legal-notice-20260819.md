## 3. 계정 삭제 — 경로 존재, 실삭제 확인

**앱 내 경로**: `POST /api/users/me/withdraw` (`backend/src/features/users/users.routes.js:17`),
휴대폰 인증 2단계 선행. 마이페이지에서 진입.

**웹 삭제 요청 URL**: `/account-deletion` 신설 완료 (2번 참조).

**실삭제 여부**: 비활성화가 아니라 **90일 유예 후 완전 삭제**다.

- 탈퇴 시: `account_status='withdrawn'` + `withdrawal_purge_at = NOW() + 90일`, 세션 즉시 전부 삭제
  (`users.service.js:539-548`, 보존일수 상수 `ACCOUNT_WITHDRAW_RETENTION_DAYS = 90`, 19행)
- 유예 만료 시: `purgeUserData()` 가 users 행과 장바구니·포인트·리뷰·QnA 등 연관 데이터를 실제 `DELETE`
  (`users.service.js:86-100`)

⚠️ **고지 불일치 발견**: 처리방침·계정삭제 페이지 어디에도 "탈퇴 후 90일 보관 뒤 파기"가 명시돼 있지 않다
(처리방침 내 "90일" 검색 0건). Google 계정삭제 정책은 삭제 소요 기간 고지를 요구하므로
보유기간 섹션에 90일 유예를 반영해야 한다. → **법률 검토 필요** (문안 임의 작성 금지 제약에 따라 미수정)

## 4. SiteFooter 정비

- 처리방침·이용약관·계정삭제·접근권한 링크: **완료** (`SiteFooter.jsx:15-18`)
- 통신판매업 신고번호: **자리 추가 완료**. `MAIL_ORDER_REPORT_NUMBER` 상수가 비어 있으면
  화면에 "미기재 (신고번호 입력 필요)"로 표시된다. **실제 번호는 사용자 입력 필요** — 임의로 채우지 않았다.
- ⚠️ 추가 발견: **상호(법인/상점명)도 푸터에 없다.** 대표·사업자번호·주소·전화만 있다.
  전자상거래법 제10조는 상호를 포함하므로 신고번호와 함께 채워야 한다. → 사용자 입력 필요

### 사업자 정보 DB 관리 검토 (제안만, 미구현)

가능하다. 근거:

- `studio_info` 테이블이 이미 "상호, 주소, 연락처, 문자 발신번호"를 보관한다 (`mysql.js:909`).
- `AdminSettingsBasicPage.jsx` 등 관리자 설정 화면 패턴이 이미 있다.

제안: `studio_info`에 사업자등록번호·통신판매업 신고번호·대표자명 컬럼을 추가하고
`AdminSettingsBasicPage`에서 편집, 푸터는 공개 API(예: 기존 사이트 설정 조회 경로)로 읽는다.
푸터가 SSR 없이 렌더되므로 로딩 전 깜빡임을 피하려면 기본값 폴백이 필요하다.
구현은 승인 후 별도 작업.
