# 코드 안전성 운영 기준

이 문서는 기능을 추가하거나 배포할 때 기존 회원, 수강권, 예약 데이터가 손상되지 않도록 지켜야 할 기준을 설명합니다.

## 배포 전에 반드시 실행할 명령

```bash
cd backend
npm test

# 실제 MySQL에 테스트용 수업·수강권을 만들었다가 삭제하는 통합 테스트
RUN_DB_INTEGRATION_TESTS=1 npm run test:integration

cd ../frontend
npm run build
```

GitHub Actions도 같은 검증을 수행합니다. 백엔드 테스트나 프런트 빌드가 실패하면 운영 서버 배포가 시작되지 않습니다.

## 데이터베이스 변경 원칙

- 운영 테이블과 컬럼은 서버 시작 시 `schema_migrations` 기록을 기준으로 한 번씩만 변경합니다.
- 이미 적용된 마이그레이션은 다시 실행하지 않습니다.
- 새로운 DB 변경은 `backend/src/shared/db/migrations.js`에 이전 항목보다 큰 ID로 추가합니다.
- 기존 데이터의 의미를 바꾸는 변경은 별도 백업과 변환 절차를 먼저 준비합니다.
- XLSX 재가져오기는 `external_import_key`로 같은 회원 수강권이나 수업이 중복 생성되지 않게 처리합니다.

## 예약과 수강권 처리 원칙

- 예약 생성, 취소, 대기 승급, 수강권 횟수 차감·복구는 하나의 트랜잭션에서 처리합니다.
- 동시 예약은 수업, 예약, 수강권 순서로 행을 잠가 정원 초과와 중복 차감을 방지합니다.
- 수업 종료 시간은 시작 시간보다 뒤여야 합니다.
- 최소 인원은 최대 정원을 넘을 수 없습니다.
- 예약·취소 마감 시간은 수업 시작 시간보다 뒤일 수 없습니다.
- 화면에는 API에서 받은 실제 수업과 수강권만 표시하며, 장애 시 예시 데이터를 실제 데이터처럼 보여주지 않습니다.
- 수강권 환불 요청의 회원 번호는 브라우저 입력을 믿지 않고 로그인 세션에서 결정합니다.
- 같은 수강권에 처리 대기 중인 환불 요청은 한 건만 허용합니다.

## 관리자와 직원 권한 원칙

- `/api/admin` 경로는 라우터 입구에서 관리자 인증을 먼저 확인합니다.
- 스튜디오의 매니저·강사 권한은 `studio_staff_profiles.user_id`로 연결된 실제 로그인 계정에만 적용합니다.
- 퇴사·비활성 상태의 직원 프로필은 연결 계정이 남아 있어도 스튜디오 관리자 권한을 부여하지 않습니다.
- 역할별 세부 권한은 `studio_role_permissions`의 기능 코드로 다시 확인합니다.

## 결제와 웹훅 원칙

- 하나의 주문과 결제 ID는 최초 연결 후 다른 값으로 덮어쓰지 않습니다.
- PortOne 웹훅 ID는 처리 전에 먼저 선점하며 같은 ID는 한 요청만 처리합니다.
- 실패한 웹훅만 재시도할 수 있고 처리 완료·무시·건너뜀 상태는 중복 처리하지 않습니다.
- 상태 변경 API에는 요청 속도 제한을 적용하며 결제 확인과 회원 예약은 로그인 회원별로 제한합니다.

## 오류 추적 원칙

- 모든 API 응답에는 `X-Request-Id`가 포함됩니다.
- 오류 응답에는 `message`, `code`, `requestId`를 포함합니다.
- 운영 환경의 500 오류는 내부 SQL이나 서버 경로를 사용자에게 노출하지 않습니다.
- 관리자 일괄 작업은 성공과 실패 건수를 분리해 표시합니다.

## 현재 자동 테스트 범위

- 트랜잭션 커밋, 롤백, 중첩 처리
- API 오류 상태와 요청 추적 번호
- 수업 입력값 검증
- 정원과 대기 정원에 따른 예약 상태 결정
- 인증·관리자 미들웨어
- API 요청 속도 제한
- 수강권 환불 입력값 검증
- 실제 MySQL 동시 예약, 대기 승급, 웹훅 중복 선점, 직원 계정 권한 연결

결제사 웹훅, 실제 문자 발송, 브라우저 전체 화면 흐름은 외부 서비스 또는 실행 환경이 필요한 통합 테스트 항목입니다.
