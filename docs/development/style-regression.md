# 화면 틀어짐 자동 검사

CSS 를 손볼 때 화면이 의도치 않게 틀어졌는지 사람 눈 대신 자동으로 확인하는 방법이다.

## 왜 필요한가

이 프로젝트의 `frontend/styles.css` 는 한 파일에 32,000줄이 넘고, 아래 특징 때문에 **규칙의 순서에 크게 의존한다.**

| 항목 | 값 |
| --- | --- |
| 고유 클래스 선택자 | 약 1,813개 |
| 여러 번 중복 정의된 선택자 | 약 565개 (31%) |
| 단독 블록으로 중복 정의된 선택자 | 139개 |
| `!important` | 467회 |
| 미디어쿼리 | 111개 |

같은 선택자가 여러 번 정의되어 있으면 **나중에 나온 규칙이 앞의 것을 덮어써서** 최종 모양이 정해진다. 파일을 쪼개거나 순서를 바꾸면 어느 규칙이 이기는지가 뒤바뀐다.

이 종류의 고장은 **빌드도 통과하고 오류도 나지 않는다.** 실제로 중복 정의된 `.site-shell` 블록 하나의 순서만 바꿔 본 결과, 페이지 폭이 1280px 에서 128px 로 무너지는데도 빌드는 정상이었다. 눈으로 보기 전에는 알 수 없는 고장이다.

## 무엇을 검사하나

화면에 그려진 모든 요소의 **최종 계산된 스타일 값**을 기록해 두고 비교한다. 픽셀 이미지 비교보다 정확하다. 폰트 렌더링 편차 같은 의미 없는 차이가 섞이지 않고, "어떤 규칙이 이겼는가"를 직접 본다.

현재 범위는 화면 39개(경로 13개 × 화면 크기 3종), 요소 약 5,478개다.

## 사용법

```bash
cd frontend
npm run build
npm run preview            # 다른 터미널에서 계속 띄워 둔다

# 바꾸기 전 상태를 기록한다
npm run style:snapshot -- before.json

# CSS 를 수정한 뒤 다시 빌드하고 기록한다
npm run build
npm run style:snapshot -- after.json

# 비교한다
npm run style:diff -- before.json after.json
```

`style:diff` 는 달라진 곳이 없으면 종료 코드 0, 있으면 1 을 돌려준다. 어느 화면의 어느 요소에서 어떤 값이 어떻게 바뀌었는지 함께 출력한다.

미리보기 서버 주소가 다르면 `STYLE_SNAPSHOT_BASE_URL` 로 지정한다. 출력 상세 개수는 `STYLE_DIFF_DETAILS` 로 조절한다.

## 검증한 것

- 아무것도 바꾸지 않고 두 번 찍으면 지문이 같다. 실행할 때마다 달라지는 값이 섞이지 않는다.
- 중복 정의된 규칙의 순서만 바꿨을 때 달라진 요소 2,443개를 찾아냈다.
- 여백 한 줄을 바꿨을 때 그 요소와 영향을 받은 부모 요소를 정확히 짚었다.
- 되돌리면 지문이 원래 값으로 돌아온다.

## 아직 덮지 못하는 곳

- **관리자 화면 전체.** 로그인이 필요하다. 중복 선택자의 상당수가 관리자 화면에 몰려 있으므로, CSS 구조를 손보기 전에 이 범위를 넓히는 편이 안전하다.
- **모달, 드롭다운, 오류 상태** 처럼 조작해야 나타나는 화면.
- **hover, focus** 같은 상호작용 상태.

## 언제 쓰나

- CSS 파일을 쪼개거나 순서를 바꿀 때
- 중복 정의된 규칙을 정리할 때
- 공통 화면 뼈대나 레이아웃 컴포넌트를 손볼 때
- 화면에 영향이 갈 수 있는 큰 수정을 한 뒤
