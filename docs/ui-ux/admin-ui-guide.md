# 관리자 UI 공통 기준

## 정보 구조

- 상단 헤더는 서비스 이동, 검색, 사용자와 알림을 담당합니다.
- 관리자 사이드바는 교육 관리와 필라테스 스튜디오 관리를 혼동하지 않도록 목적별 메뉴를 제공합니다.
- 화면 제목, 조회 조건, 핵심 작업, 목록 순으로 배치합니다.
- 반복 업무 화면은 장식보다 검색, 비교, 선택과 일괄 작업의 효율을 우선합니다.

## 공통 요소

- 버튼은 실제 동작이 연결된 경우에만 노출합니다.
- 아이콘 버튼에는 접근 가능한 이름이나 툴팁을 제공합니다.
- 검색, 필터, 페이지네이션은 결과 수와 현재 상태를 함께 보여줍니다.
- 표는 헤더, 빈 상태, 오류 상태, 로딩 상태를 구분합니다.
- 모달과 드로어는 닫기, 취소, 저장 동작과 키보드 포커스를 제공합니다.

## 화면 크기

- 데스크톱 관리가 기본이지만 1024px에서도 핵심 작업이 잘리지 않아야 합니다.
- 좁은 화면에서는 표를 억지로 축소하지 않고 필요한 경우 명시적인 가로 스크롤을 제공합니다.
- 헤더 검색과 주요 작업 버튼은 줄바꿈이나 축약으로 서로 겹치지 않아야 합니다.
- 모바일 회원 화면은 375px, 390px, 430px 기준으로 별도 확인합니다.

## 상태와 피드백

- API 실패를 성공처럼 표시하지 않습니다.
- 저장, 삭제, 발송, 결제와 환불은 진행 중 중복 클릭을 막고 결과를 안내합니다.
- 데이터가 없을 때와 불러오지 못했을 때의 문구를 구분합니다.
- 권한이 없는 기능은 프론트엔드 노출과 별개로 백엔드에서도 차단합니다.

## 변경 검증

- 기존 API와 상태 계약을 바꾸지 않았는지 확인합니다.
- 데스크톱 1920, 1440, 1280, 1024 해상도에서 레이아웃을 확인합니다.
- Console Error, Page Error, Network Error와 가로 넘침을 기록합니다.
- 관리자 UI 리디자인 smoke와 실제 백엔드 integration 테스트를 구분합니다.
